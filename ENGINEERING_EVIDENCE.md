3. Production `ModelIntelligencePipeline` is a single four-stage graph: language normalization, entity recognition, semantic fusion, evidence arbitration. The forensic `Analyze` clones the model and runs the same stage graph, so the report is observing production fusion/arbitration rather than a separate classifier.
4. Both entity recognition and semantic fusion's decision text use primary fields only. In fusion, explicit/generalized artifact-role grammars also run against the title/name source only. The field-by-field source-cue scan includes descriptions solely in diagnostics/evidence text, explicitly marked “diagnostic only unless field is primary.” Therefore a description hit cannot create a fused category or reach arbitration. This is an intentional safeguard, not an accidental failure of the arbitration threshold.
5. Arbitration first requires a fused category. It then applies typed structural and lexical gates; unresolved lexical evidence can promote at confidence >=60 and quality >=25 with a lexical cue. On the 318 residual records, fusion generally never establishes a category, so arbitration records `NO_FUSED_CATEGORY`. Lowering arbitration thresholds would not fix this specific gap and would not make the ignored description hits usable.

### Population-linked findings

- On 50 residual records, `metadata.description` is present. In field-diagnostic matching, **10/50** have one or more source-cue matches and **40/50** have none. The hit records remain unresolved because description matches are not inference inputs. Examples include strong explicit descriptions (`lightbox`, aircraft/fuselage, memorial plaque) and ambiguous/incidental ones (`stand`, `prop`, `bird`, `toy`, `connector`). This is a coverage limitation with an intentional design reason, not proof that all ten should be promoted.
- Current semantic-cue self-test covers title/name positives and description negatives (for example, “stood up” and a frame's leg/base). It does not contain a positive description-only case or a 3MF archive integration case proving that extracted description provenance is preserved through the production pipeline. This is the main regression-test gap for any proposed description-role improvement.
- The residual population's broader pattern remains: 290/318 have primary title/name evidence, 315/318 have no lexical cue match, and entity recognition returns none for all 318. The primary bottleneck is not geometry parsing or arbitration looseness; it is conservative semantic coverage for names/forms, compounded by a deliberate description-prose quarantine. Folder locations cannot repair this because the user confirmed they mix manual and app-generated categorization.
- Analyzer structure/print-method evidence does not resolve the semantic gap. Object count, mesh reachability, filament profile, dimensions and AMS/nozzle settings are not sufficient category signals.

### Defect vs. design tradeoff

- **Confirmed design limitation:** description text can contain the only explicit object role, but is never a promoting input to fusion. Examples from this fixture include a lightbox description and a memorial plaque description; current diagnostics can recognize them, but the category remains Uncategorized.
- **Not confirmed as a defect:** excluding all general description text. The current false-positive controls show why broad prose matching is unsafe, and the dataset contains many instructions and marketing statements. Do not append descriptions to the existing title string or let generic cue matches promote from descriptions.
- **Potential observability gap:** evidence-quality/root-cause output collapses “no inference from primary evidence” and “explicit secondary description signal held back by policy” into `NO_FUSED_CATEGORY`/low evidence. The evidence string contains diagnostic matches, but the structured cause does not expose a distinct `SECONDARY_ROLE_HELD_FOR_REVIEW` reason. This makes the population harder to triage and can make a deliberate policy look like missing vocabulary.

### Recommended focused repair and acceptance criteria

Implement a separate, typed **description-role evidence** extractor rather than broadening the general semantic text. It should accept only bounded constructions that state what the printable artifact is (for example, “lightbox I designed,” “simple refrigerator style magnet,” or “frame for an ultrasound photo”), keep the exact source field/span and matched rule, reject accessory/action/instruction mentions (for example, a model “has a stand,” “stood up,” “fits into a base,” or “requires a prop/stand”), and remain independent from subject/entity cues. Candidate promotion must be category-specific, confidence-calibrated and observable in arbitration; do not weaken the global confidence/evidence gates.

Required validation before accepting that repair: a positive/negative matrix using records from the 50-description cohort; a small real-archive integration fixture verifying extraction, HTML cleanup, truncation behavior and evidence provenance; unit coverage for exact decision/arbitration behavior; replay of the 343 original unresolved rows with every new candidate and every changed result enumerated; retained Death Star, TF2 prop, stand/frame and three “not found” controls; then a fresh isolated 1,789-file scan with unchanged inventory/accounting, zero unexplained regressions, and human precision review of all new promotions. No database writeback, auto-organization, or release should follow from replay alone.
